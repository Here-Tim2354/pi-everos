# 读写时机

pi-everos 在什么时刻读记忆、什么时刻写记忆。

## 读

| 时机 | 接口 | 条件 |
| :--- | :--- | :--- |
| 会话里第一次提问 | `POST /memory/search` | 提问短于 8 个字符就不查，等下一轮。整场只查一次，结果冻结，之后每轮注入同一段 |
| 模型调用 `memory_search` | `POST /memory/search` | 语义检索，模型自己决定查什么 |
| 模型调用 `memory_list` | `POST /memory/get` | 按时间倒序列出，不做检索 |
| `/memory-list` 命令 | `POST /memory/get` | 给人看的，第一页 10 条 |
| `/memory-status` 命令 | `GET /health` | 只看连得上没有 |

自动召回带 `include_profile`，用户画像跟检索结果一起进来。画像不参与排序，命中与否都会返回。

## 写

| 时机 | 接口 | 条件 |
| :--- | :--- | :--- |
| 每轮结束 | `POST /memory/add` | 只发锚点之后的新增对话。工具输出、思考过程、系统提示都不发 |
| 模型调用 `memory_add` | `POST /memory/add` | 跟上一行走同一条队列，按顺序发 |
| 会话结束 | `POST /memory/flush` | 缓冲区里还有没提炼的才发。只等请求发出去，不等返回 |

写入的对话不会立刻可检索。提炼是异步的，markdown 落盘之后还要等索引同步。

## 提炼由谁决定

`/add` 只把消息放进缓冲区，边界由 EverOS 自己判断。命中边界时 `/add` 的返回是 `extracted`，说明缓冲区已经空了，退出前不用再催。

## 关掉自动行为

配置文件里 `recall: false` 关掉自动召回，`commit: false` 关掉自动提交。三个工具和 `/memory-list` 命令不受影响。

## 出错时的取舍

- 召回失败重试，上限 3 次，之后本场不再试。
- 上下文被压缩、锚点已经不在上下文里时，跳过本轮提交。宁可不发，也不重发。
- 提交失败退回上次服务端确认的位置，下一轮连同这批一起重发。
- 退出时最多等 5 秒让提交落地，再等 1.5 秒把提炼请求发出去。
