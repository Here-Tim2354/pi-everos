# 长期记忆

每轮对话都会自动提交给 EverOS 提炼，会话开头也会自动注入召回片段。下面说的是例外情况。

## 看检索结果

查不到就直说，不要换词重试。常见原因两个，用户问起再解释：

- 提炼是异步的，刚结束的对话可能还没进索引。
- 记忆按项目分开，别的仓库里做的决定在这里看不到。

命中时原子事实比摘要可靠，摘要是概括过的。

## 想核对存了什么

`memory_list` 按时间倒序列出条目，不做检索。用户问「你记得什么」，或者怀疑检索漏了，用这个。用户画像用 `memory_type: "profile"` 单独取。

## 该主动记的时候

三种情况调 `memory_add`：用户说「记住这个」；出现会长期成立的变化，比如换了工具、改了约定、推翻了旧决定；要纠正一条过时的记忆。

写成带主语和时态的事实陈述：「Tim 决定部署只用 Docker，不引入其他依赖」。

记忆只能追加，删不掉也改不了。纠正旧说法就是再写一条明确的陈述，靠检索排序压住旧的。旧条目还在库里，被查到时以新说法为准。

不记这些：凭据（密码、令牌、密钥、证件号）、一次性的调试信息和临时路径、代码里一眼能看到的函数名和目录结构、还没确定的猜测。

## 怀疑记忆没在工作

让用户运行 `/memory-status`，别自己猜原因。日志在 `~/.pi/agent/pi-everos.log`。
