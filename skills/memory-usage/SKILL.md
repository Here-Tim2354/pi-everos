# 长期记忆

pi 每轮对话都会自动提交给 EverOS 提炼，会话开头也会自动注入一段召回片段。所以多数时候不用额外做什么。这个技能说的是例外情况。

## 什么时候主动查（memory_search）

- 用户提到「上次」「之前说过」「你还记得吗」，而当前对话里没有相关内容。
- 要下一个跟历史有关的判断：技术选型、命名习惯、部署在哪台机器。
- 排查问题时怀疑以前踩过同一个坑。

查的时候用一句完整的话说清意图，别只丢关键词。命中为空是正常结果，换一种说法再试一次就够，不要反复重试。

## 什么时候主动写（memory_add）

- 用户明确说「记住这个」。
- 出现会长期成立的事实变更：换了工具、改了约定、推翻了旧决定。
- 要纠正一条已经过时的记忆。

写法是一条完整的事实陈述，带主语和时态，例如「Tim 决定部署只用 Docker，不引入其他依赖」。「用户可能喜欢 pnpm」这种模糊表述没有价值。

日常对话不用手动写，自动提交已经覆盖。

## 什么不该记

- 密码、令牌、密钥、证件号这类凭据。
- 一次性的调试信息、临时路径、当天的时间地点。
- 从代码里一眼能看到的东西：函数名、目录结构、依赖版本。
- 还没确定的猜测。要被推翻的推测比没有记忆更麻烦。

## 结果怎么看

- 每条记忆带时间戳，可能过时。跟当前对话冲突时以当前对话为准，并考虑用 memory_add 写一条更正。
- 原子事实比摘要可靠，摘要是概括过的。
- 工具结果里的条目 id 只在需要删除时才有用，平时不用管。
