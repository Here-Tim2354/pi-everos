# 长期记忆

pi 每轮对话都会自动提交给 EverOS 提炼，会话开头也会自动注入一段召回片段。多数时候不用额外做什么，这个技能说的是例外情况。

## 主动查：memory_search

用在当前对话里没有、但以前聊过的内容上。典型场景：用户提到「上次」「之前说过」「你还记得吗」；要下一个跟历史有关的判断，比如技术选型、命名习惯、部署在哪台机器。

检索时用一句完整的话说清意图，别只丢关键词。结果如实转述给用户。

**查不到就直说，不要反复换词重试。** 常见原因有两个，用户问起再解释：

- 提炼是异步的，刚结束的对话可能还没进索引。
- 记忆按项目分开，在别的仓库里做的决定在这里看不到。

## 主动记：memory_add

三种情况值得调用：用户明确说「记住这个」；出现会长期成立的变化，比如换了工具、改了约定、推翻了旧决定；要纠正一条已经过时的记忆。

写成完整的事实陈述，带主语和时态，例如「Tim 决定部署只用 Docker，不引入其他依赖」。「用户可能喜欢 pnpm」这种模糊表述没有价值。

日常对话不用手动写，每轮自动提交已经覆盖。

## 什么不该记

- 密码、令牌、密钥、证件号这类凭据。
- 一次性的调试信息、临时路径、当天的时间地点。
- 从代码里一眼能看到的东西：函数名、目录结构、依赖版本。
- 还没确定的猜测。要被推翻的推测比没有记忆更麻烦。

## 结果怎么看

- 每条记忆带时间戳，可能过时。跟当前对话冲突时以当前对话为准，并考虑用 memory_add 写一条更正。
- 原子事实比摘要可靠，摘要是概括过的。
- 工具结果里的条目 id 只在需要删除时有用，平时不用管。

## 怀疑记忆没在正常工作

让用户运行 `/memory-status`，它会把地址、作用域、服务器状态一起列出来。别自己猜原因。日志在 `~/.pi/agent/pi-everos.log`。
